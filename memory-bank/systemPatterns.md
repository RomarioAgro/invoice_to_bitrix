# System Patterns

## Архитектура

`telegram_app` управляет in-memory состояниями, нормализует подпись к файлу как описание и вызывает `recognition`, `dadata` и `bitrix`; `config` строго загружает INI/env; Docker использует host network только для доступа к loopback SOCKS5.

## Принятые решения

Telegram использует `HTTPXRequest` с SOCKS5. Bitrix и DaData используют отдельные `httpx.AsyncClient(trust_env=False)`. Результат DaData кэшируется внутри активного счёта. Техническая обработка не ставится в очередь, а занимает счётчик доступной ёмкости.

## Инварианты

Не логировать токены, Base64 и полный текст. Не использовать proxy для Битрикс. Не принимать второй активный счёт и не отправлять production-тест без подтверждения.
